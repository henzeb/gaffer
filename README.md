# Gaffer

Gaffer Direct (overlay player controls) and Gaffer Inspect (player/stream analyser), built as bookmarklets and as modules for the Gaffer Chrome extension from `src/direct/`, `src/capture/` and `src/inspect/`, with shared code in `src/shared/` and the pure media code (manifests, MP4 muxer, TS converter) in `src/media/`. See `SPEC.md` for the structure.

## Build

```bash
npm install
npm run build                  # both, writes dist/
node build/build.js direct     # one target (capture | direct | inspect)
```

`npm run build` also copies the extension shell (`extension/`) with the modules into `dist/extension/`, ready to load unpacked (Chrome 138+, developer mode). The icon PNGs in `extension/icons/` are generated from `icon.svg` with `npm run icons` and committed.

The build bundles each tool with esbuild into `dist/<tool>.js` (one minified line, sourcemap in `dist/<tool>.js.map`) and writes the bookmarklets `dist/gaffer-<tool>-bookmarklet.js` and `dist/gaffer-<tool>.html`. Capture (`dist/capture.js`) has no bookmarklet of its own: the Direct bookmarklet runs capture first, then Direct. `__BUILD__` is replaced by the build timestamp. The bookmarklet may not contain a `%` anywhere (also not in CSS: use `from`/`to` keyframes); the build stops with the source location when it does.

All interface texts live in `lang/en.json` (§13.1 of the spec). Direct and Inspect call `t(key, params)` from `src/shared/i18n.js`; the build bundles only their own keys. The extension uses `msg(key, params)` from `extension/i18n.js` and `data-i18n` attributes, backed by `_locales/` that the build generates from the same file. `test/unit/lang.test.js` checks that used and defined keys match.

## Development version

```bash
npm run dev                    # keep it running; GAFFER_DEV_PORT picks another port (default 8423)
```

`npm run dev` builds **Gaffer (dev)** into `dist/extension-dev/`, with the modules in `dist/extension-dev/modules/`. Load that folder once as an unpacked extension (developer mode, "Allow user scripts") instead of the regular Gaffer, not next to it. On every save in `src/` the modules are rebuilt and the dev shell loads them, re-registers and restarts Direct in the open tabs. On every save in `extension/` or `lang/` the shell is rebuilt and reloads itself (a change in `lang/` also rebuilds the modules). A save in `build/` restarts the dev server, so changes to the build code apply without restarting `npm run dev` by hand. The signal goes over a WebSocket on `ws://127.0.0.1:<port>`; without `npm run dev` the last loaded version keeps working and the shell reconnects when the server is back. The popup shows "Development version" with the time of the last build, and the icon carries a "dev" badge.

## Release

Before a tag, check the extension by hand on real sites with `docs/release-checklist.md`. The texts for the Chrome Web Store are in `docs/store-listing.md`; the privacy policy is `PRIVACY.md`.

```bash
git tag v1.2.0 && git push origin v1.2.0   # release
npm run release -- 1.2.0                   # what the workflow runs: dist/gaffer-extension-1.2.0.zip, modules and manifest with that version
npm run extension                          # only pack dist/extension/ into dist/gaffer-extension-<version>.zip
```

Pushing a `vX.Y.Z` tag runs `.github/workflows/release.yml`: tests, then `npm run release`, then a GitHub release with the extension zip. Upload that zip in the Chrome Web Store developer dashboard; Chrome updates installed copies from there. The extension fetches no code: Direct, capture and Inspect are in the package.

## Test

GitHub Actions runs `npm test` on every push to `main` and every pull request (`.github/workflows/ci.yml`).

```bash
npm test                       # build, then unit tests (test/unit/) and e2e tests (test/e2e/) in parallel, with the duration per file
node --test --test-name-pattern="portal" test/e2e/direct-quality.test.js
GAFFER_TIMING=1 npm test       # Direct's wait times in real time instead of scaled by 0.2
```

Requirements: Chrome for Testing (`npm run chrome` installs it into `~/.cache/gaffer/chrome-for-testing/`; `CHROME` points at another binary) and `ffmpeg` (with libx264, libx265 and libmp3lame, as in the Ubuntu package). The test media in `test/fixtures/media/` is generated by `test/fixtures/make.sh` on the first run.

`pages/vendor/hls.min.js` and `pages/vendor/dash.min.js` are copies of hls.js and dash.js (version in `<name>.version`, license in `<name>.LICENSE`). `npm run vendor:hls` and `npm run vendor:dash` update them to the newest release (or `npm run vendor:hls -- 1.7.4` for a given version); `npm test` warns when a newer release exists.

The harness (`test/e2e/harness.js`) starts a local server for `test/e2e/pages/` and a headless Chrome with a temporary profile, `--no-sandbox` and `--mute-audio` (the test media carry a sine tone). Pages are served from `http://127.0.0.1:<port>/`; the same server on `http://localhost:<port>/` acts as a second origin for the cross-origin iframe.

`direct-record.test.js` replaces the file picker with a writer in memory (`window.__gafferWriter`, see §9 of the spec) and checks the written files with `ffprobe`. `test/unit/media.test.js` checks the manifest parsers and the muxer against the generated media.

`extension.test.js` builds a test variant of the extension in a temporary directory (the modules from `dist/` with Direct marked by a number, all-sites permission already granted), loads it into Chrome for Testing and drives the popup as a tab (`popup.html?tab=<id>`). A Web Store update is simulated by writing a new module into that directory and dispatching `runtime.onUpdateAvailable`. `*.test` host names map to the test server. `dev.test.js` does the same for Gaffer (dev), with user scripts turned on via `chrome://extensions`.

`dev.test.js` starts `npm run dev` (`startDev` from `build/dev.js`) on a free port into a temporary directory, loads Gaffer (dev) and triggers module and shell rebuilds directly. The harness turns on developer mode in the test profile, which `chrome.runtime.reload()` needs.

`pages/lib/track.js` is loaded first on every page. It records listeners on `window`, `document` and media elements and intervals added after `__track.mark()`, and `__snapshot()` returns the DOM (attributes sorted) and video state for before/after comparisons.

Single steps against a page, for debugging:

```bash
node test/e2e/test.js '["HOVER:#vid","KEY:r","WHEEL:300,200,-100,2"]'
PAGE=live.html node test/e2e/test.js '[...]'
BM=inspect node test/e2e/test.js '[...]'          # direct | inspect | path to a bookmarklet file
DIRECT_BM=/path/to/old/gaffer-direct-bookmarklet.js npm test   # run the e2e tests against another build
```

Steps: `WHEEL:x,y,delta[,modifiers]`, `DRAG:x1,y1,x2,y2`, `TAP:x,y[,count]`, `CLICK:<button title prefix>`, `CLICKSEL:<css>`, `MOVE:x,y`, `HOVER:<css>`, `KEY:<key>`, `WAIT:<ms>`, or any JS expression to evaluate.
